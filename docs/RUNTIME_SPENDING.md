# Контроль расходов в runtime — #18 / панель #19

[English](RUNTIME_SPENDING.en.md)

Контроль подключён к существующим legacy-раундам, повтору роли, ручной проверке
моделей и Hermes StepOperations. Это не только standalone ledger. При пустом
`SPEND_POLICY_FILE` модели **не отправляются**, даже если API-ключи и Hermes уже
настроены. Mock, классификация, сохранённая история и GET статусов остаются
детерминированными. Нового Director/модельного маршрутизатора нет.

## Политика и запуск

`SPEND_POLICY_FILE` — абсолютный путь к выделенному, контролируемому владельцем
JSON без секретов. По умолчанию пуст. [Шаблон](contracts/runtime-spend-policy.example.json)
намеренно просрочен, с неизвестными ценами/привязкой аккаунта и выключенными
признаками проверки. Копирование шаблона не разрешает inference.
[Схема](contracts/runtime-spend-policy.schema.json) описывает все поля.

Перед включением маршрута оператор подтверждает фактический endpoint, модель,
допустимые роли/качество, границы провайдера и **все** категории тарифа: вход,
выход, reasoning/cache, фиксированные и дополнительные сборы. Имя модели,
подписка или слово free не доказывают нулевую цену. Неизвестные данные блокируют
отправку. `account_sha256` связывает профиль с настроенным API-ключом; сам ключ
в JSON/журнал не записывается. Агент не читал credentials и не создавал рабочую
политику для Zorin. Готовые тестовые метаданные не переносить на живые сервисы.

На проверку — до 24 часов; старые/невалидные JSON, дубли полей, не-UTF-8,
nonfinite values, ссылки/reparse/hard links и файлы >128 KiB отклоняются.
Путь из браузера не принимается. После настройки сервер перезапускается обычным
способом; остаются loopback, Basic Auth и SSH tunnel.

### Верхняя граница, не средний расход

`tariff` хранит целые micro-USD за миллион входных/выходных токенов и фиксированный
`request_micro_usd`. Резерв = проверенный максимум входа + максимум выхода + сбор,
с округлением каждой части вверх. Входной предел должен соответствовать реально
обеспеченной границе провайдера, включая обрамление SDK; размер HTTP payload также
ограничивается. Ожидаемое фактическое число токенов без tokenizer неизвестно:
панель показывает подтверждённые максимумы, не выдуманную точную оценку.

Для платного OpenRouter обязателен отдельный `upstream_tariff`: upstream caps
не должны включать сборы, уже добавленные в полную верхнюю границу. В запрос
передаются `provider.max_price`, запрет fallback, требование поддержки параметров
и текстовый режим. Для OmniRoute оператор обязан проверить реальные ограничения
фиксированного gateway-маршрута, включая его внутренние аккаунты/комбинации;
непроверенный gateway не становится безопасным от локальной декларации цены.
[Официальный контракт OpenRouter](https://openrouter.ai/docs/guides/routing/provider-selection).

Цена ответа не равна автоматически долларовой оплате. `reported_cost_unit`
должен быть явно подтверждён как USD либо credits с проверенным `credit_micro_usd`.
Иначе стоимость остаётся null, а максимальный резерв сохраняется. Токены/числовая
сумма из ответа сохраняются отдельно, вместе со снимком применённой политики;
raw prompts, HTTP bodies, argv и ключи в финансовый журнал не попадают.
Платёж/квитанция и остаток подписки остаются неизвестными. Провайдерский cost —
учёт использования; он не доказывает отдельную банковскую транзакцию.
[Usage Accounting](https://openrouter.ai/docs/cookbook/administration/usage-accounting).

## Разрешение владельца

Серверные ceilings сами денег не разрешают. Все новые scope стартуют
`allow_paid=false`, бюджет 0. Платной задаче нужны разрешения **общего лимита,
проекта и задачи** для точного маршрута. Проверка моделей с фиксированным prompt
потребляет общий лимит. Другой ключ/проект/operation ID не создаёт новый общий
бюджет. В legacy используются только существующие configured references;
проверенный бесплатный маршрут ставится первым, без дорогого автоматического
fallback. В Hermes сохраняется явный фиксированный маршрут директора.

В панели владелец выбирает scope/маршрут, вводит общий лимит (не доплату) и
подтверждает разрешение. Оно **не запускает модель**. Сумма ограничена сервером,
маршрут — политикой. Более дорогая/другая модель требует отдельного разрешения.
Версия бюджета и hash показанной политики защищают от устаревшего подтверждения;
повтор потерянного ответа использует тот же approval ID/тело. Actor берётся из
проверенной Basic Auth, не из JSON. Записываются до/после, кто/когда, маршрут,
scope, разрешённое окно и новая сумма.

Учтённые расходы, токены, запросы и резервы **не обнуляются** при обновлении
политики или ручном продлении окна. Обновлённая серверная политика отзывает старые
платные маршруты; бесплатные могут использовать новые проверенные метаданные.
Бесплатный маршрут не расходует исчерпанный денежный лимит, но учитывает квоту,
время, unknown и overrun. Отзыв платного API не возвращает уже потраченные деньги.

## Атомарность и неизвестный исход

Резерв всех scope и StepOperation записываются одним SQLite commit на одной
connection, через savepoints существующего ledger. Разрешение отправки расходуется
один раз непосредственно перед транспортом; HTTP/SDK работает вне write-lock.
Сохранённый результат модели и финансовый outcome фиксируются одной транзакцией.
Ошибка фиксации результата не превращается в разрешение повторного inference.

Hermes проверяет настоящие HTTP payloads перед отправкой: модель, контекст, schema,
размер, output cap, отсутствие tools/functions, умножения генераций и fallback
списка. Сохраняются существующие one-child/one-inference ограничения. SDK deadline
ограничивается политикой. Данные usage из JSON/SSE выделяются в ограниченный buffer;
неполные данные не объявляются нулевыми. Перенаправления/ambient proxies не используются
прямыми адаптерами, POST автоматически не повторяется.

Timeout/неизвестный исход сохраняет максимальный резерв и блокирует новые вызовы
общего account, включая другой проект/ключ. При restart неотправленные разрешения
отзываются, отправленные становятся unknown; автоматического replay нет. 429
сохраняет cooldown/Retry-After. Перерасход сохраняется и блокирует новые вызовы;
новое подтверждение не стирает unknown/overrun. Верифицированное финансовое
разрешение unknown остаётся отдельной работой, без опасной кнопки «обнулить».

## API и данные

- `GET /spending/status`, `GET /spending/tasks/{id}?mode=mock|hermes&run_id=...`:
  выбранный маршрут/причина, оценка, scope, резерв/известный расход/остаток,
  токены, попытки, ограничения, даты, история разрешений и safe usage evidence.
- `POST /spending/approvals`: owner-only, CSRF, explicit confirm, idempotency,
  expected revision и policy SHA. Нет тарифов/actor/file path из клиентского JSON.
- Версия runtime schema 1 проверяется до других app DDL; неизвестная версия
  отклоняется, данные не очищаются. Backup/restore учитывает финансовые таблицы и
  unresolved state. История не мигрирует старые неизвестные вызовы в ложный ноль.

## Проверка и границы

Backend/API/Chromium tests используют настоящие временные SQLite/HTTP/runtime
пути и синтетические upstream responses/тарифы: default deny, owner confirmation,
последний параллельный резерв, rollback с StepOperations, restart, смена аккаунта,
stale price, fixed fees, quota, unknown, overrun, free-first, токены/единицы,
потерянный ответ, RU/EN/mobile и XSS. Это проверка приложения, не живой invoice.

Живые тарифы/caps/usage Hermes/OmniRoute, Codex CLI/subscription dispatch,
полный сквозной code/QA/Reviewer/PR и OS isolation этим этапом не принимаются.
Контроль действует в известных путях приложения; произвольный процесс владельца
вне приложения не становится sandbox. Ручной ChatGPT/latest_available/High —
отдельный поддерживаемый маршрут, без cookies/scraping и скрытого inference.
