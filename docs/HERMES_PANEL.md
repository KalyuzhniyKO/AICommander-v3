# Подготовка панели #19: сохранённая история Hermes

**Обновление 27.10.2026:** [действия владельца под бюджетным контролем](HERMES_OWNER_CONTROLS.md) расширяют исходный read-only этап. Они не выполняют код или QA.

[English](HERMES_PANEL.en.md) · [Issue #19](https://github.com/KalyuzhniyKO/AICommander-v3/issues/19)

В существующей панели добавлен выбор **Режим истории → Hermes · сохранённое
планирование**. По умолчанию выбран Mock. Для выбранной задачи читаются только
её процессы соответствующего контракта: `/taskflow/*` или `/taskflow/v2/*`.
Mock и Hermes не смешиваются, даже если у одной задачи есть оба вида истории.
Ошибка чтения v2 не переключает панель на mock-данные.

В режиме Hermes доступны:

- сохранённые статусы, версии, роли, события и содержимое типизированных артефактов;
- отдельный Reviewer плана, предложенный план и сохранённые замечания;
- источник артефакта: модель, SDK revision, correlation ID операции и hash входов;
- журнал операций: running/result_ready/unknown/succeeded/failed/discarded,
  отметка запроса отмены и время обновления;
- окончательная отмена процесса с актуальной версией и idempotency key.

Новые модельные вызовы, создание Hermes-процессов, шаги, продолжение и согласование
в этой подготовке UI недоступны. Они не отправляются даже через общий обработчик
mutations: для v2 разрешена только команда cancel выбранного процесса. Это
ограничение интерфейса, а не новое правило серверного API: существующий backend v2
сохраняется без изменений. Авторизация, Host/CSRF и version/idempotency проверяются
сервером как прежде. Редактирование проектов/задач не вызывает модели.

Потерянный ответ отмены можно повторить **с тем же ключом и телом**, без создания
новой операции. До разрешения потерянного ответа переключение режима/процесса/
задачи заблокировано. HTTP409 перечитывает состояние и требует нового решения
владельца. Операция unknown не перезапускается. Отмена не доказывает возврат оплаты,
завершение внешнего worker или разрешение unknown; эти действия остаются у
доверенного оператора по [протоколу восстановления](HERMES_TASKFLOW.md).

Обновление явное: кнопка «Обновить» перечитывает snapshot и metadata. Нет
автоматического poll/retry или вызовов inventory/inference. Не удалось прочитать
операции — показывается ошибка, а не сообщение об отсутствии истории. Смена языка
и размера экрана не изменяет данные; пользовательские тексты не переводятся.

**Граница результата:** real-артефакты v2 — планирование, а не выполненный код.
Даже `done` — согласованные артефакты; в панели нет подтверждённого Git diff,
реального QA или проверенного отчёта расходов. Квоты и доступность провайдеров
не проверяются и не изображаются зелёными. Прежний mock workflow работает отдельно.

## Проверка

[QA и команды](qa-issue-19-panel.json). Браузерные тесты запускают настоящий
uvicorn и временную SQLite. V2-артефакты создаются **тестовым директором** в fixture,
не установленным Hermes: это UI-контрактные проверки, не live-результат #14.
Проверяются смешанная история одной задачи, четыре роли, источник/экранирование,
состояния операций, отмена и потерянный ответ, ошибки GET, запрет запуска моделей,
RU/EN и mobile overflow. Старые mock-сценарии также выполняются.

Скриншоты — **синтетические тестовые данные**, Chromium viewport emulation,
не Safari/iPhone и не UI работающего сервера Zorin:
