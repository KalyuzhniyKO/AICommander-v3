# Панель сохранённых пакетов QA — подготовка #19

[English](LOCAL_REVIEW_PANEL.en.md)

Панель показывает пакеты [локального прогона](LOCAL_RUN.md): требования/риски,
Git diff, сохранённые pytest/Django checks, exit codes, stdout/stderr, обрезку
вывода, блокеры и запрос независимого ревью. Это отдельный раздел страницы,
не артефакты выбранной задачи Mock/Hermes. SQLite и состояния taskflow не меняются.
Нет запуска команд/моделей, approve/reject/retry, публикации PR или merge.
Полные #15/#16/#19 остаются открытыми.

## Включение

По умолчанию раздел выключен. Владелец явно указывает **абсолютную выделенную
папку evidence** внутри разрешённого рабочего пространства, а не source,
worktrees, домашнюю папку или всю файловую систему. Например, после passing demo
из LOCAL_RUN.md в `.env` сервера:

```dotenv
LOCAL_REVIEW_ROOT=/absolute/workspace/AICommander-v3/.aicommander-local-runs/passing-1/evidence
```

Используйте настоящий абсолютный путь на машине приложения. На Windows допустим
абсолютный native путь к evidence. Перезапустите приложение обычным способом;
доступ остаётся через HTTP Basic и SSH tunnel на loopback, как в
[инструкции MacBook](MACBOOK_PANEL.md). Эта настройка не включает Zorin, Hermes,
OmniRoute, network calls или автоматический поиск каталогов. Приложение не создаёт
папку. Отсутствующая/относительная папка или symlink/reparse отклоняются.

В evidence находятся непосредственные подкаталоги с 32-значными lowercase hex
run IDs. Demo уже создаёт такой layout. Пакеты из разных evidence-каталогов можно
копировать вручную в отдельную выделенную папку, сохраняя ID и **все пять файлов
байт-в-байт**, без объединения/перезаписи конфликтов. Git-примеры passing/failing
не подключаются автоматически: их имена не run IDs.

## Контракт чтения

- `GET /local-reviews`: `{enabled, runs:[{run_id}]}`. Список ID не является
  проверкой целостности. Только один уровень, максимум 100 **всех** записей;
  превышение возвращает 503 без частичного списка. Нет pagination/discovery.
- `GET /local-reviews/{run_id}` принимает только ID, не путь, URL, upload или glob.
  Возвращает manifest, `manifest_sha256`, `qa_report`, четыре UTF-8 текста в
  `artifacts` и явные границы: `integrity_valid=true`, `authenticated=false`,
  `current_source_verified=false`, `ready_for_pr=false`, `ready_for_merge=false`.
- Только после проверки существующим verifier: ровно пять ожидаемых файлов,
  связи QA/manifest/diff, SHA-256/размеры и состояния. Manifest ≤16 KiB,
  каждый артефакт ≤8 MiB, суммарно ≤12 MiB; regular files без symlink/reparse
  и hard links. Detail дополнительно связывает run ID с именем каталога.
- Reader возвращает те же байты, которые проверил, без повторного чтения файлов
  после проверки. Это ограниченная файловая проверка, **не** защита от враждебных
  процессов/гонок файловой системы или OS sandbox. Владелец должен контролировать
  выделенную папку и её права.
- Повреждённый/отсутствующий/неполный/не-UTF-8 пакет даёт 409 без непроверенных
  текстов или файловых путей; неверный ID — 404, выключенный detail — 404,
  недоступный root/index — 503. Все маршруты требуют существующую авторизацию;
  POST/approve отсутствуют.
- HTTP JSON проходит существующую best-effort redaction. Показанные тексты могут
  быть маскированы; manifest hash относится к исходным проверенным байтам на
  диске, не к заново сериализованному HTTP JSON. Файлы на диске не меняются.

## Значение статусов

«Целостность пакета проверена» подтверждает согласованность сохранённых данных.
Хеши не удостоверяют автора, доверенность команд или текущие файлы worktree.
Даже passing показывает **успех в сохранённом прогоне**, обязательные независимое
ревью и решение владельца; `review-request.md` не заключение Reviewer.
`source_current_at_export` остаётся исторической записью. Панель не вызывает
`session.is_current()` и не объявляет актуальность исходников сегодня.

Выбор/обновление/ошибка сразу очищают предыдущий результат. Запоздавший ответ
после refresh отбрасывается. Список не подменяется примерами при ошибке. Текст
выводится через textContent, без HTML/Markdown-исполнения. Поддерживаются RU/EN
и узкий экран. Раздел не наследует кнопку согласования выбранной Mock-задачи.

## Проверка и границы

Новые API tests используют побайтовые копии опубликованных синтетических
passing/failing пакетов. Chromium запускает настоящий локальный HTTP-сервер
и временную SQLite; проверяет оба исхода, stdout, переключение языка, 390px,
ошибки целостности/index, refresh/запоздалый ответ, выключенный режим и XSS в
самостоятельно пересчитанном пакете. Такой пакет по-прежнему не аутентифицирован.
Регрессия LOCAL_RUN выполняет настоящие процессы pytest/Django на fixtures.

```bash
python -m pytest -q tests/test_review_api.py tests/test_localrun.py
RUN_UI_TESTS=1 python -m pytest -q tests/ui/test_review_panel.py
RUN_UI_TESTS=1 python -m pytest -q
```

PNG проверены локально: passing RU, failing EN/mobile и ошибка целостности.
Это Chromium и синтетические данные, не живой Zorin, Safari или приёмка устройств
владельца. Скриншоты не содержат credentials и не подменяют результаты тестов.
Новых зависимостей, фоновых jobs, миграций БД, SSH/deploy, GitHub runtime wiring
или независимого Reviewer нет. Полная цепочка Hermes → Codex → QA → Reviewer
→ PR/CI остаётся последующими этапами.
