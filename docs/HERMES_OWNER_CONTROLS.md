# Действия владельца в Hermes-панели — #19

[English](HERMES_OWNER_CONTROLS.en.md)

После runtime-контроля расходов #18 панель может управлять **планированием**
Hermes: новый процесс, optional Architect, лимит шагов, start/resume, один model
step, pause/cancel, согласование/отклонение сохранённого плана. Это текущие v2
контракты, не второй Director и не code executor.

## Условия доступности

`GET /taskflow/v2/capabilities` сообщает `owner_controls_version=1` и
`runtime_budget_guarded=true` только при наличии hooks бюджетного runtime.
Старый/недоступный capability ответ не включает новые действия. История и
operations metadata должны быть успешно прочитаны. Новый inference доступен
только при включённой серверной конфигурации Hermes; это не проверка живой квоты.

При выключенном SDK остаются отмена и решения по сохранённому плану, не требующие
моделей. При неизвестных capabilities остаётся отмена известного процесса.
Running/result_ready/unknown operation или ошибка чтения операций блокируют новые
шаги и повтор. Unknown никогда не становится автоматическим inference retry.

## Что выполняют кнопки

- Создание/start/resume/pause изменяют lifecycle; сами модель не вызывают.
- «Следующий шаг» — явное действие владельца. Backend резервирует общий/проектный/
  задачный бюджет и проверяет политику непосредственно перед transport dispatch.
  При default settings запрос модели не отправляется, UI показывает причину.
- Architect добавляется только явным checkbox нового плана; нужен дополнительный
  шаг. Поле step limit сохраняет серверный предел.
- «Согласовать план» принимает только сохранённое планирование. Оно не подтверждает
  код, QA, независимое ревью, бюджет или право merge/deploy.
- Отмена окончательная и не возвращает неизвестные/потраченные расходы.

Для всех изменений используются прежние Basic Auth, CSRF, expected version и
idempotency key. Потерянный ответ шага повторяется тем же телом/ключом; сохранённый
результат/бюджет не вызывают второй inference. Конфликт/unknown перечитывает
metadata и блокирует дальнейшие действия до явного решения. Mock v1 сохранён.

## Проверки

Пять новых Chromium-сценариев используют настоящий локальный HTTP/SQLite и
реальный budget guard, с fixture SDK/RPC и явно синтетическим zero-price профилем:
полный план с Architect, pause/resume, согласование после выключения SDK;
default-deny без вызова RPC; потерянный model-step ответ без повторного inference;
capability failure с доступной отменой; unknown operation с запретом нового шага.
Ранее проверявшийся read-only просмотр сохранён; чистые plan decisions теперь
доступны и без SDK. Code/QA flags во всех проверках остаются false.

Это не live Zorin/пилот и не независимый code Reviewer. Публичный HTTP source
manual ChatGPT из #18 не подтверждает API prices/gateway caps. Реальная конфигурация
расходов остаётся задачей оператора; working policy не создавалась. Сквозные
код/QA/Reviewer/PR и приёмка устройств владельца остаются зависимыми этапами.
