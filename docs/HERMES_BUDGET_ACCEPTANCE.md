# Подготовка бюджетной live-приёмки Hermes

[English](HERMES_BUDGET_ACCEPTANCE.en.md)

Утилита `python -m backend.app.taskflow.live_acceptance` проверяет две синтетические
цепочки (3 и 4 роли), сохранение решения владельца, replay в отдельном процессе
без credentials и max_steps=1. Всего максимум 8 вызовов bridge, без retries/fallback.
Это планирование, не исполнение кода и не QA результата модели.

Старая незакоммиченная утилита из live-readiness не изменена. Новая версия подключает
RuntimeSpend к той же SQLite connection, что и Taskflow, заново при каждом открытии.
Общий и проектный лимиты сохраняются между цепочками. Неизвестная стоимость остаётся
null; неизвестный исход останавливает приёмку и сохраняет финансовые резервы.

CLI требует `--allow-inference`, `--workspace` (новый абсолютный каталог) и
`--spend-policy` (актуальный файл проверенной политики). Ключ и настройки Hermes/
OmniRoute поступают JSON через stdin, не через argv или переменные окружения.
Никакие рабочие `.env` не загружаются. Политика не создаётся из тестовых fixtures.
Для платного маршрута дополнительно требуется явно согласованный общий потолок
`--approved-micro-usd`; по умолчанию 0. Серверные ceilings не заменяют разрешение.
Разрешение CLI применяется к global/project/task через существующий RuntimeSpend.

Каталог создаётся с mode 0700, SQLite эксклюзивно с mode 0600. Данные сохраняются
после успеха и ошибки: автоматическое удаление финансового evidence запрещено.
После unknown не запускать другую копию/новую БД ради обхода блокировки; сначала
разобрать сохранённый исход. Утилита сама ничего не возобновляет и не повторяет.
Профили bridge остаются временными; эта утилита не создаёт и не отзывает API-ключи.
Оператор должен использовать отдельный ограниченный ключ и обеспечить его отзыв.
