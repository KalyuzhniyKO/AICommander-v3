# Совместимость Python и macOS — политика AICommander 3.0

[English](PYTHON_COMPATIBILITY.en.md) · [Требования](PRODUCT_SPEC.md) · [GitHub Issue #58](https://github.com/KalyuzhniyKO/AICommander-v3/issues/58)

## Обязательные принципы

1. **Актуальные версии Python.** Объявленная поддержка конкретной minor-версии означает успешную установку зависимостей, `compileall`, `pip check` и подходящие реальные тесты в CI. Новый стабильный Python проверяется отдельно вскоре после релиза; до завершения проверок нельзя объявлять его поддерживаемым или несовместимым без доказательств.
2. **Кроссплатформенность.** Backend-тесты на Ubuntu и Windows; обязательная проверка на GitHub-hosted **macOS ARM64** с реальными backend-тестами и Chromium/Playwright UI. macOS ARM64 runner подтверждает совместимость с архитектурой Apple Silicon, но **не является** тестом на MacBook Air M4 и **не заменяет** Safari/WebKit-тестирование.
3. **Исправление причин, а не сокрытие несовместимостей.** Проблемы в своём коде устраняются с регрессионными тестами; ограничения и обновления сторонних пакетов проверяются отдельно. Не маскировать ошибку `continue-on-error`, условным skip, исключением платформы или бездоказательным понижением версии Python.
4. **Ограничения зависимостей только с обоснованием.** Допустимы воспроизводимый lock/pin, ограничения безопасности, минимально поддерживаемая upstream-версия и документированная несовместимость. Для временного upper bound указывать пакет и диапазон, воспроизведение/ссылку upstream, причину, альтернативы, ответственность и дату пересмотра. Пин не должен подменять работу по совместимости.
5. **Безопасная проверка.** В GitHub Actions не использовать реальные API-ключи моделей, production БД, домашние серверы и реальные задачи пользователя. Браузерные тесты используют временную БД и заглушки провайдеров.

## Фактическое покрытие на 18.10.2026

| Окружение | CI / статус |
|---|---|
| Ubuntu, Python 3.11, 3.12, 3.13, 3.14 | Обязательные `pip check`, `compileall`, `pytest` |

Источник состояния — [workflow `foundation.yml`](../.github/workflows/foundation.yml), подтверждённый [CI PR #56](https://github.com/KalyuzhniyKO/AICommander-v3/actions/runs/39107082409): все указанные jobs завершились успешно. Изменения в последующих коммитах требуют новых проверок.

## Новый Python и независимость runtime от QA fixtures

- [Python 3.15.0](https://www.python.org/downloads/release/python-3150/) стал стабильным **09.10.2026**. [Issue #58](https://github.com/KalyuzhniyKO/AICommander-v3/issues/58) отслеживает первичную проверку: установка runtime отдельно от `requirements-dev.txt`, импорт/запуск offline API, затем dev/pytest/браузерные проверки на доступных платформах.
- `requirements-dev.txt` содержит `Django>=5.2.8,<5.3` **только для тестовых Django QA fixtures**, не для runtime приложения. [Django 5.2](https://docs.djangoproject.com/en/5.2/releases/5.2/) официально поддерживает Python 3.14 начиная с 5.2.8; текущая документация Django **не заявляет** поддержку Python 3.15. Это технический риск тестовой зависимости, а не доказательство несовместимости FastAPI runtime.
- Границу `Django<5.3` требуется отдельно проверить и документировать либо заменить тестовой матрицей совместимых версий Django. Нельзя произвольно снимать upper bound до проверки QA fixtures, но и нельзя использовать его как бессрочный повод не тестировать новые Python.
- При появлении новой стабильной minor-версии: завести compatibility Issue; попробовать установить/выполнить core-тесты в отдельной среде; классифицировать собственные дефекты и проблемы upstream; устранить или задокументировать конкретный временный blocker; добавить необходимую версию в CI и критерии приёмки. Экспериментальная проверка может быть отдельной и явно обозначенной, но её отсутствие или успех не выдавать за полную поддержку.

## Критерии приёмки изменений

- Все заявленные Python/OS комбинации проходят актуальный обязательный CI; реальные названия job, commit SHA, ссылки на лог и failures доступны в PR.
- macOS ARM64 backend и Chromium тесты обязательны, не подменяются Linux эмуляцией.
- Для новой версии Python есть воспроизводимый отчёт о проверках и зависимостях, а не догадка по `python_requires`.
- Не появились фиктивно зелёные тесты, необоснованные ограничения интерпретатора, platform skips или downgrade; временные исключения зарегистрированы с доказательствами и планом исправления.
- Разработка ведётся в отдельной ветке/PR, merge/deploy допускается только после явного решения владельца.
