# Панель владельца: taskflow с MacBook

Панель PR #30 интегрирована с объединённым offline taskflow (PR #31). Основная ветка репозитория **AICommander-v3 — `main`**. Выполнение на Zorin через реальные Hermes/OmniRouter/Codex и бюджет остаётся отдельным этапом.

## Запуск тестового экземпляра

Используйте отдельный checkout/worktree и тестовую SQLite, Python 3.11–3.14 (Python 3.14 — также в macOS ARM64 CI):

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
cp .env.example .env
cp config/models.example.json config/models.json
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

Запишите пароль в серверный `.env` как `PANEL_PASSWORD`, логин — `PANEL_USER=owner`. Не используйте ключ провайдера как пароль. `.env` исключён из Git. Browser HTTP Basic обрабатывается браузером; frontend не содержит секретов и не хранит их в localStorage.

Запустите `python -m backend.app.main`. Привязка — `127.0.0.1:8000`. При отсутствующем/коротком пароле все ресурсы отвечают 503, без авторизации — 401. Поддерживается один процесс uvicorn: startup восстанавливает только прерванные **legacy-задачи**, процессы taskflow сохраняют свои состояния и версии. Публичное размещение и прямой bind в LAN не поддерживаются.

На MacBook создайте SSH tunnel (замените логин и адрес):

```bash
ssh -N -L 127.0.0.1:8000:127.0.0.1:8000 zorin-user@zorin-host
```

Можно использовать адрес Zorin из VPN/Tailscale. Откройте `http://127.0.0.1:8000` и введите логин/пароль панели. HTTP Basic передаётся по loopback внутри зашифрованного SSH tunnel. После настройки подключения управление задачами выполняется в браузере. Реальный Zorin/tunnel в этой проверке не запускался.

## Сценарий владельца

1. Создайте проект и задачу. Задача — контейнер; её прежний `tasks.status` не является состоянием taskflow.
2. Нажмите «Новый процесс»: `POST /taskflow/tasks/{task_id}/runs`, стандартный лимит — три шага. Селектор сохраняет доступ к истории процессов, включая отменённые и согласованные.
3. «Запустить процесс» отправляет `start`; «Следующий шаг» отправляет один `step`. Analyst → Architect → Developer передают **сохранённое типизированное содержимое** следующей роли. UI показывает этапы, артефакты, входные ID, статус, версию и расход шагов.
4. «Пауза» — `block`, «Продолжить / Повторить» — `resume` после blocked/failed. Исчерпанный лимит нельзя обойти; создайте новый процесс.
5. «Отменить процесс» — `cancel`: конечное состояние `cancelled`, продолжать его нельзя. В mock-taskflow нет фонового внешнего исполнения. Существующий отдельный legacy API сохраняет cooperative stop для HTTP-вызовов моделей.
6. После трёх артефактов `awaiting_owner`: подтвердите или отклоните через `owner-decision`. Отказ блокирует процесс; resume возвращает готовые артефакты на согласование без пересоздания. `done` обозначает **только согласованные mock-артефакты**. Код, QA, Git merge и deploy не выполняются.

В панели нет автоматического вызова legacy моделей. Прежние раунды показываются отдельно как история. Offline executor PR #33 сохранён как самостоятельная библиотека: он не подключён к Mock Director, поэтому UI не выдаёт вымышленный git diff или результат QA. Статус стоимости неизвестен; taskflow не вызывает модели.

## Согласованность запросов

Контракт `/taskflow/*` не изменён: см. [TASKFLOW](TASKFLOW.md) и frozen JSON Schema. Каждая команда использует новый `idempotency_key` и текущую `expected_version`. Двойной клик блокируется на время запроса.

- При HTTP 409 UI перечитывает процесс, показывает доменную ошибку и ждёт нового решения пользователя. Команда не повторяется автоматически.
- При сетевой ошибке/timeout или HTTP 5xx результат неизвестен. Кнопка «Повторить запрос» отправляет **тот же URL, тело, expected_version и ключ**, даже если выбран другой процесс. Остальные изменения заблокированы до разрешения неопределённого запроса.
- После ответа или replay UI перечитывает актуальный snapshot; сохранённый старый ответ команды не заменяет более новую версию.
- После перезагрузки браузера UI читает сохранённые процессы; незавершённая HTTP-команда не отправляется автоматически. Повторы создания/команд в открытой странице защищены idempotency; ключи не сохраняются в браузерное хранилище.

## Миграции и доступ

`init_db` сохраняет старую схему, вызывает taskflow migration 1 и независимую panel migration 1. Под `BEGIN IMMEDIATE` создаются проекты/legacy-решения, добавляется nullable FK `project_id`, старые задачи привязываются к Foundation. Trigger задаёт Foundation для прямых legacy INSERT без project_id. Такой способ совместим с непустой SQLite при включённых foreign keys. БД раннего PR #30 с уже существующими проектами/решениями принимается без потери данных. Повторные и конкурентные миграции проверены; ошибка миграции панели откатывает её DDL/данные. Taskflow-артефакты, события и версии не переписываются.

Все маршруты, включая `/taskflow/*`, JSON Schema/OpenAPI и статические файлы, требуют HTTP Basic. Изменяющие запросы дополнительно требуют `X-AICommander-Request: 1`; чужой Origin отклоняется. Host ограничен loopback. CORS не включён. CSP запрещает сторонние скрипты и iframe. Настроенные ключ/пароль маскируются в JSON, включая ошибки валидации; дополнительно маскируются Bearer и sk-… . Это best-effort redaction: не вводите другие секреты в задачи/артефакты.

## Двуязычный интерфейс и лента Mock Director

Панель открывается **на русском**. В верхней части страницы можно выбрать **English** и вернуться к русскому без перезапуска задачи. Переключение меняет только подписанные элементы UI и не переводит тексты задач, решения владельца, данные сервера или содержимое артефактов. Само переключение не отправляет запросы изменения на сервер; после обновления страницы снова используется русский. Документация: [English README](../README.en.md).

В блоке **«Ход работы · демонстрация директора»** отображаются исключительно данные уже сохранённого процесса: исходное требование, его статус/число шагов и фактические идентификаторы созданных mock-артефактов. Текст отображается с HTML-экранированием. Это **не чат с Hermes**, не реальный планировщик модели и не подтверждение Git diff, QA или исполнения кода. Полное содержимое артефактов доступно в отдельном разделе ниже.

Этот интерфейс не добавляет никаких backend API, разрешений на merge/deploy, сетевых подключений или расходов моделей. Для реального Hermes/OmniRoute потребуются отдельные интеграции и проверки.
